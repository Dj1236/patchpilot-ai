An autonomous repair agent with the brakes built in.

PatchPilot AI takes one bug report for an approved Python repository and returns one tested, reviewable patch. The model only reads and proposes. Allowlists, patch rules, budgets, the sandbox, grading and the approval gate are enforced in code outside it.

Problem → control

Generating a patch is the easy part.

A language model can write a plausible fix in seconds. Trusting it is the hard problem: the fix may be wrong, the repository may be hostile, and a write to GitHub cannot be taken back. PatchPilot treats each of these as a boundary enforced in code, never as an instruction in a prompt.

01Plausible is not correct

The agent writes both the fix and the test that “proves” it.

ControlIts own checks give only candidate_verified. Only hidden tests, run afterwards on a tree rebuilt from the pinned start, decide resolved.

02Code under repair is untrusted

Issue text, source files and test output can carry prompt injection or hostile code.

ControlText stays in labelled untrusted blocks. Code runs only in a container with no network, a read-only root and no credentials. The host never imports it.

03Autonomy needs bounds

Loops, retries and model switches can burn money and repeat side effects.

ControlEvery request is reserved in a spend ledger before it is sent. Turns, tool calls, proposals and time are capped. One model per process, no fallback.

04Writes need a person

An agent that can push can push the wrong thing to the wrong place.

ControlA person approves the exact proposal by typing its digest. Only drafts, only one allowlisted repository, never a merge.

Interactive architecture

Three trust zones, one direction of trust.

The host orchestrator is trusted and never runs repository code. The sandbox is where untrusted code runs. The evaluator holds hidden tests the agent never sees. Pick a flow to trace it, or select any component for its rule and the tests behind it.

    Current status

    What is proven, what is simulated, what is pending.

    Verified locally

    • 1,054 tests pass (3 skipped, 1 expected failure), 94% coverage, Ruff and strict mypy clean
    • Sandbox network, filesystem, privilege and resource limits, attacked in a real Docker container
    • Allowlist, path confinement, patch policy, hidden-test isolation
    • Spend ledger, pacing, attempt caps, no model fallback
    • Checkpoint validation and fail-closed resume
    • Baseline and repair on four synthetic tasks, graded by hidden tests

    Simulated

    • Model: scripted, hand-written answers in every completed run
    • GitHub writes: a local fake GitHub API (tests/fake_github.py) for approval binding, idempotency and reconciliation
    • Docker host: Colima on macOS, not the Linux reference environment

    Pending

    • Real model: all 8 generation requests to free-tier Gemini got HTTP 503, so no model output and no graded result exist yet
    • Real GitHub draft PR: not yet made
    • Hosted CI: GitHub Actions runs have not started on this account; no CI gate has passed
    • Real open-source tasks: the four tasks are synthetic, written for this project
